# Packard Bell PB430

The user reports a **24% average benchmark improvement** over the stock BIOS. The separate RAM throughput result improved from **13.6 to 17.3 MB/sec**, with effective read/write access times of **242/121 ns**. These are physical observations, not emulator measurements. The complete winning settings and benchmark set are not yet recorded.

The combined ACCPROF timing test improved measured throughput from 14.0 to 15.7 MiB/s. Choose **Chipset > RAM Timing > Memory Timing > Fast** to use that combination. Choose **Manual** next to retain it and unlock individual RAM timings. Normal uses the original read/write timings and normal refresh. Profiles do not change bank layout, cache size or CPU clock. The [timing table](docs/register-map.md#timing-options-at-a-glance) explains the available fields and the evidence behind them.

Chipset has six groups: General, RAM Timing, Cache and Memory, Refresh, Bus and ROM Timing, and Shadow. The redundant Fast Memory Writes shortcut is removed. Use Write CAS Width and Write CAS Precharge in RAM Timing instead. Refresh Period offers 15, 30, 60 and 120 microseconds; **120 us (Slow)** is the previous Slow Refresh option. Normal and F9 Defaults use 15 us and stock write timings. Fast selects 120 us and faster writes. Editing Refresh Period changes the profile to Manual and keeps the other timings. Presets reset RAM and refresh fields, while preserving independent cache, bus, ROM and shadow choices.

**Devices > COM3 / COM4 Addresses** offers the four original address pairs, including reversed 2E8h / 3E8h. The default remains 3E8h / 2E8h. UART choices retain IRQ conflict filtering.

**Chipset > Bus and ROM Timing > ISA Clock Divider** lists /2, /3, /4, /5, /6, /8 and /10 in numeric order. Each divisor appears once. The default is marked on its actual value: /4 for the tested 33 MHz configuration, or /3 for the other stock jumper setting. These are final motherboard-clock divisors, including the controller's fixed divide by two. On the tested setup, /3 predicts about 11.1 MHz; physical measurement is still needed. The VGA is local bus. Use the clear-CMOS jumper if a selection prevents startup. See [the selector table and limits](docs/stock-feature-audit.md#isa-clock-divider). Monitor type is jumper-controlled. Power saving and passwords remain deferred global tasks.

The visible RAM test follows the Presario order on cold and warm POST: memory and shadow setup, RAM test, then peripheral initialization and floppy seek. Both L1 and L2 remain disabled during the test. The selected DRAM timings apply before testing, on the tested 33 MHz jumper setting with L1 selected in Setup and qualified cache hardware. Unsupported configurations keep the stock timing table. The old L2 conflict reads are removed. After device initialization and the final Setup gate, the firmware restores stock timing prerequisites, runs the complete stock cache sequence, and reapplies the saved runtime settings. A passing POST test does not establish long-term stability or test L2. See the [RAM-test recovery lessons](docs/porting-lessons.md#ram-testing-and-recovery) before changing this order.

AT refresh is always enabled, including when loading older saved choices. **Chipset > Cache and Memory > DRAM Read Burst** controls DRAM read bursts and defaults to Enabled. Disabled is available for comparison; Normal and Fast preserve this choice. Reset restores the enabled baseline before the stock cache sequence, then the saved choice applies before the RAM test. Posted Writes is removed and forced off. Refresh Period appears only in Refresh. Hidden Burst Refresh controls access to Refresh Active Time, Refresh Precharge and Refresh Burst Count. Disabled locks all three without discarding saved values. AT Refresh Burst is removed and its field returns to the stock value. Cache Wait Control remains adjustable: enabling it reduced measured write access time to 121 ns. Reads were still near 270 ns at that stage; later timing changes reached 242 ns.

Normal startup restores AT refresh before reading RAM, even without a timing-trial marker. Flash this image to recover from the removed AT Refresh setting. If the invalid-CMOS warning remains after saving, boot plain DOS and run `ACCCMOS > CMOS.TXT`. The utility in `build/diagnostics/ACCCMOS.COM` captures two reads of saved CMOS bytes without writing data. Saved records pass the firmware checks; the cause of the physical warning is still unconfirmed.

Cache and Memory groups **Cache Burst Reads**, **Cache Read X-2-2-2**, **Cache Burst Writes** and **Cache Write X-2-2-2** together. Each X-2-2-2 choice is locked until its parent is enabled, and only applies while that parent is enabled. Saved child choices are retained. The read parent was previously named Cache to CPU Burst. All four choices default off; the two read choices slowed this board. The write choices are experimental ACC2087-derived controls; that manual restricts them to write-back operation. They do not switch the CPU's cache mode. Refresh also offers **CAS Before RAS Refresh**, default off to retain the stock behavior. Its enable bit was clear in the supplied live dump. Reset restores the original register fields before the stock cache sequence. `ACCDUMP` includes register37 so the applied write choices can be checked.

A detected RAM mismatch restores stock timings before the existing safe-default retry. Turning power off or resetting during an unfinished RAM test preserves saved settings and does not create a failure notice. Only a comparison failure starts recovery. Enter Setup with Delete to replace unstable timings. A verified save permits another trial. Ctrl+Alt+Del during testing deliberately retries the saved settings. RAS Timeout remains enabled in both Normal and Fast. Read CAS Width of 1T froze this board with normal pulse timing, but worked with Earlier Read Pulse Timing. Earlier Write Pulse Timing also allowed Uncached Write Wait at 0 WS. Setup help describes both tested pairings. Controls remain independent for experiments. The latest user result is 17.3 MB/sec versus the original 13.6 MB/sec, with 242/121 ns effective read/write access time. The complete settings and long-term stability are not established by that result.

The older `ACCPROF` utility expects its original baseline: Manual, Write CAS Width 1T, Write CAS Precharge 1T, 120 us refresh, RAS Timeout disabled, and the other timing fields at Normal values. It refuses an already-applied Fast profile. `ACCDUMP` can read either configuration. See the [probe evidence](docs/hardware-evidence.md#combined33mhz60ns-timing-profile) and [live register capture](docs/register-map.md#live-timing-snapshot-and-probable-acc2168-model).

The separate `--cache-burst` experiment made RAM reads slower on hardware. Use the normal image. The former Fast Memory Writes shortcut is now covered by the individual RAM timing controls. Existing saved timings are retained. The tested write rate rose from18.7 to21.6 MiB/s. See the [setting and test procedure](docs/hardware-evidence.md#fast-memory-writes-in-setup). The [ACCORDER diagnostic](docs/hardware-evidence.md#address-order-diagnostic) compares nearby and widely spaced reads without changing timing registers.

This port composes the shared bAIos firmware with ACC2168 chipset and ACC3221 controller adapters. It keeps the Presario-800 POST, Setup, keyboard, clock, disk and boot mechanisms. It uses the modular source layout without the M919 cache profiles, certification state or PCI adapters.

The user reports repeatable physical boots with the `stock-cold-resume` image, programmer SUM32 `013A7200`. Later settings changes require a new physical check. The emulator does not reproduce the board's DRAM banks, SRAM or electrical timing.

From the repository directory, build with:

```powershell
powershell -NoProfile -File pb430/tools/build.ps1
python -B pb430/tools/test-port.py --case all
```

The build writes `pb430/build/baios-pb430.bin` (131072 bytes) and `baios-pb430-system.bin` (65536 bytes). The physical image uses the accepted Presario 60 MHz Cirrus video BIOS, followed by 32 KiB of FF and the new F000 system ROM. The builder checks the input hashes, retained bytes, reset target and zero-sum system checksum.

An experimental early interleave image is available with `python -B pb430/tools/build.py --interleave`, under `pb430/build/interleave/`. It requires the detected four4MiB-bank layout and tests the mode before building live firmware state. It preserves the accepted VGA and cache sequence. See [interleave experiment and POST codes](docs/hardware-evidence.md#early-interleave-experiment). The normal build remains unchanged.

VGA60 remains the default. `python -B pb430/tools/build.py --vga60` also writes it under `pb430/build/vga60/`. Use `--vga50` for the matching VGA1.41 50 MHz image under `pb430/build/vga50/`. The two images share the system BIOS and differ only at VGA offsets `08E7` and `7FFF`. Use `--stock-vga` for the original video ROM under `pb430/build/stock-vga/`. This is a separate provider. `--output build/review/example` selects a directory inside the PB430 build tree for any variant. The [shared update pipeline](../docs/port-updates.md) builds and checks both clock variants without changing approved root images.

The C1 read-pulse trial is withdrawn after a failed check and a hard lock. The utility refuses C1 before hardware access. See [the diagnostic limits](docs/hardware-evidence.md#one-cycle-cas-read-experiment). For the slower-refresh and timing probes, build `python -B pb430/diagnostics/build-acc-timing.py` and use the [DOS probe instructions](docs/hardware-evidence.md#slower-refresh-and-register18-trials). The [combined read trials](docs/hardware-evidence.md#read-trials-with-fast-memory-writes-enabled) preserve the selected write timings and refresh period. For the 0B and refresh-divider comparisons, restore the baseline required by that probe.

POST and Setup use the existing text layout, colors, help, themes and hotkeys. ADS Delay defaults to Disabled, as specified by the AMI manual. Auto disables ADS while preserving the saved Manual choice. RAS Timeout defaults to Enabled. POST shows the selected L1 setting even while early startup holds the cache off. When L2 is selected, POST reports its detected size without an Off suffix. L2 follows L1 at the top of POST, with one blank line before the RAM test. The short SRAM check uses the shared word-pattern owner while the adapter preserves reference controller setup and warm reuse. All timing choices take effect after Save and restart. Existing saved cache, ADS, boot, refresh and write choices are retained when their record is upgraded.

Fast Boot is on the Boot page and defaults to Off. On skips the visible RAM test at and above 1 MiB. POST then shows the full installed RAM amount. Memory detection and mandatory initialization still run, and the full installed memory remains available. Pause and Esc work during the RAM test. Press Delete before or during the test to enter Setup. As on the Presario, Delete stops the test at its next keyboard service point and opens the existing Setup screen. The default boot order is CD-ROM, floppy A, then hard disk, with the fourth slot Disabled. Valid saved choices remain unchanged. Use F9 Defaults and F10 Save to adopt the new defaults.

Onboard video requires both C000 and E000 shadow mappings, so those fields remain fixed. External video can use its own ROM with shadow disabled. C800, D000 and optional E000 shadows copy the complete selected window before protecting it. Leave them disabled where a card uses the area as RAM. Shadow cacheability remains enabled by default to preserve the stock behavior; AMI recommends disabling it for compatibility. Shadow write protection defaults to Enabled. External cache requires an unambiguous OEM size result and enabled processor cache. An ambiguous SRAM result displays `Present / unknown` and remains disabled.

The Ports page offers Disabled and the four standard UART addresses, plus compatible or bidirectional parallel operation. It rejects two onboard UARTs on the same IRQ. Floppy enable, drive types and A/B swap use the existing handlers. The Drives page owns the primary IDE controller and its master/slave records. The port preserves ATA, ATAPI, EDD, CD boot, option-ROM discovery, saved boot order and fresh-key retry. The RTC, PS/2 mouse, keyboard, RAM test and public interrupt services use the shared owners.

Cold startup probes all four DRAM views, applies a supported OEM map, then measures physical RAM with an alias-aware count. An unsupported bank pattern stops with EA instead of selecting a guessed map. Ordinary warm reset preserves the memory map, measured count and onboard-video origin. Shutdown 05/0A returns before destructive work.

Changing Internal Cache or External Cache and saving selects full cold initialization on restart. This establishes the reference cache configuration before activation. An unchanged Save or ordinary Ctrl+Alt+Del retains warm reset. If Save reports an error after writing chipset choices, a later Ctrl+Alt+Del compares the choices that actually persisted.

Run one named check with `--case serial`, `--case cache` or another case listed by `--help`. Each check writes its result under `pb430/build/test-results/`. The suite builds its candidate in `test-results/current/image/` and preserves the current root ROM. Native display checks compare every character, attribute and retained font byte. Independent hardware models check DRAM/SRAM behavior and the data-sheet UART IRQ encoding. They execute the production firmware owners and do not establish physical stability.

Native checks require the recorded PB430-capable 86Box executable at `tools/deps/86box-b10408/86Box.exe`. The installed 6.0 release lacks PB430. The matching model also has a primary-UART IRQ selector defect; physical encoding remains correct, and the independent serial proof covers it. See [validation](docs/validation.md), [hardware evidence](docs/hardware-evidence.md) and [POST codes](docs/post-codes.md).

Before cleanup, stop the emulator and run:

```powershell
powershell -NoProfile -File pb430/tools/clean-build.ps1 -WhatIf
```

The port retention policy keeps current ROMs, listings, dependencies, captures, failed diagnostics and the nested task worktree. It removes completed disposable VMs and media only after their consumers finish. A `.retain-diagnosis` file protects an active failed case. Original references remain unchanged.
