# bAIos v0.2.0: Mitsubishi MP386/25

This release adds the Mitsubishi MP386/25 port for the 25 MHz 386DX, TI TACT83000 chipset and Intel 82385 cache controller. The tested board has 2 MiB onboard and four 4 MiB banks on its expansion card.

Repository release v0.2.0 contains MP386 firmware with its existing 0.1.0 identity and 10/20/2026 ROM date. It includes the shared legacy IDE initialization fix and the MP386 DOS A20 handoff fix.

## Programmer images

| File | Bytes | Purpose | Programmer SUM32 |
| --- | --- | --- | --- |
| `baios-mp386-v0.2.0.bin` | 65,536 | Combined system ROM | `007F2100` |
| `baios-mp386-v0.2.0-even.bin` | 32,768 | Low/even byte EPROM | `003F4F5B` |
| `baios-mp386-v0.2.0-odd.bin` | 32,768 | High/odd byte EPROM | `003FD1A5` |

SUM32 is the additive sum of every byte in the selected file. `CHECKSUMS.txt` also contains SHA256 hashes. `README.txt` contains these programming and usage notes.

Keep the original ROMs and save the existing configuration before programming. For a board with two EPROMs, use the split files in the established low/even and high/odd sockets. The combined file contains both lanes and is not a replacement for either individual EPROM. Power-cycle the board after programming.

The system uses the VGA ROM on the installed video card. The download does not contain a VGA ROM. Use these images only for the matching Mitsubishi board.

## Configuration and behavior

If POST reports invalid configuration, press Enter to save defaults or Delete to open Setup. F10 saves Setup changes and restarts. The lost OEM Setup disk is unnecessary for bAIos.

bAIos uses part of the OEM configuration storage for its own settings. Restoring OEM ROMs alone does not restore the OEM configuration. The board switches still control onboard routing, expansion-memory selection and the cache request. Setup's Devices page displays the switch guide. Turn power off before changing switches.

POST uses the shared RAM-test controls and reports a fixed 32 KB cache after qualification. Fast Boot defaults to Disabled. Enabling it limits the RAM sweep to below 1 MiB while retaining detected capacity. Chipset Setup exposes 57 decoded timing controls and keeps page mode and interleave automatic.

The shared IDE routine initializes Auto CHS disks before media access and restores their parameters after reset. LBA disks retain their existing path. The MP386 boot handoff releases its motherboard A20 override so HIMEM.SYS can control A20 through the keyboard controller. The Landmark DMA-mode error with EMM386 loaded remains an unconfirmed benchmark compatibility issue. Run that benchmark without EMM386.

An interrupted timing trial selects working defaults on the next start and preserves its saved payload. Power loss and intentional reset do not create a RAM failure or consume a RAM retry. Only an actual failed comparison starts the controlled RAM-failure retry. A fully verified Save releases safe timing selection.

## Accepted limits and validation

With 18 MiB installed, the contiguous range ends at `FE0000`. Extended memory is 15,232 KiB. bAIos reports 632 KiB of base memory after its 8 KiB reservation. The OEM reports the same extended limit with a 640 KiB base count. Recovery of the last 2 MiB remains deferred.

A separate CAS-before-RAS refresh-mode selector is not identified. The exposed CAS-to-RAS control sets a delay. The user guide with the missing chipset register definitions remains unavailable. Use the working timing defaults. Faster choices need separate stability testing on the physical board.

Bench testing covers POST, Setup, expansion RAM, shadowing, cache and DOS startup. Software checks cover native reference comparisons, cold/warm boot, memory restoration, cache qualification, Setup persistence, interruption recovery, legacy IDE initialization and A20 control. Synthetic checks do not qualify physical timing margins. Shared IDE initialization also changes the other maintained ports. Their regression checks cover that correction separately from retained hardware behavior.

Bench results came from the earlier candidates. The final rebuild uses the existing bootstrap hook once and has not been flashed on the board.

Build from the repository root with Python and NASM from the existing toolchain:

```powershell
python -B mp386/tools/build.py
```

The output is `mp386/build/baios-mp386.bin` and its even/odd files. This build needs no vendor ROM input. Reference-comparison tests require the separately supplied OEM images. Original vendor ROMs, manuals and complete disassemblies are excluded from the public source and release assets.
