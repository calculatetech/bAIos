# Shared PIO0–4 support

## Outcome and scope

All maintained ports use the shared ATA mode service. It understands PIO0 through PIO4, negotiates the fastest mode permitted by the device, port limit and requested ceiling, restores that mode after reset, and reports the effective result. A port can cap the shared driver. Controller-specific timing programming is a separate adapter; absence of such an adapter does not establish that a separate IDE controller cannot accept PIO4.

Base is `bde974a8eae55178c8a75d11509c1fb2e04a6182` on the existing `task/m919-ide-completeness` branch, in the primary checkout. This continues the user's IDE priority. Earlier checkpoints are immutable. The user supersedes the earlier PIO3/4 deferral, conservative Auto decision and exact revision0D/33MHz mode restrictions in `m919/docs/plans/M919-010-tuning.md`. The supported673A PCI IDE function is qualified by identity, function, enable policy and compatibility-mode usability. Revisions are informational. No IDE timing-clock selector remains. Physical margins at every clock through50MHz are not established by that software capability contract. Remaining cache migration BAIOS-003 stays planned. Existing physical candidates remain available.

Shared owners are `shared/src/firmware/ide-pio.inc`, discovery/reset in `bios.asm` and `pc/primary-ata.inc`, inventory in `pc/ata-inventory.inc`, state in `pc/state.inc`, and Setup/reporting in `firmware/setup.inc`. M919 owns its controller qualifier, full timing tuple and saved request layout. Other ports retain their established controller enable and bus-cycle configuration. No unknown controller registers are programmed. The generic adapter's explicit supported-hardware precondition is an ATA host that honors IORDY while retaining its existing strobes. Device acceptance cannot verify this physical host property. A port ceiling limits the common driver when the controller has a documented restriction. The absence of programmable timing registers is not such a restriction. PIO3/4 on each physical non-M919 host remains unqualified until tested or independently established. No software IORDY polling loop or fabricated controller enable bit is added.

## Decisions and reference evidence

The ATA/ATAPI-5 draft T13/1321D revision3 defines IDENTIFY word49 bit11 for IORDY, word53 bit1 for validity of words64–70, word64 advanced modes, word67 cycles without IORDY and word68 cycles with IORDY. PIO3/4 selection needs the advertised capability, IORDY support and an adequate cycle time. SET FEATURES03 with count08..0C selects PIO0..4. Device completion must precede host acceleration. Primary source: <https://www.seagate.com/support/disc/manuals/ata/d1153r17.pdf>.

The original M919 normal owner233C..2445 and table2328..233B select all five modes. Use its complete board recipe, including48..4F: 3/6/B,2/5/8,1/4/5,0/3/2,0/3/0. The generic UMC manual differs for two fast fields; the board-specific recipe owns this port. Establish the physical field ordering from that consumer and the manual, independently of the existing test model. All four original M919 images use the same mode triples without a host-clock argument. IDE41 remainsC9, including bit04 clear. The user explicitly requires supported modes on all revisions and supported board clocks through50MHz. The former exact0D/33MHz vetoes are removed; no new clock-specific values are invented. FSB and actual PCI clock remain distinct. The original AMI divider policy does not establish electrical margins at PCI50MHz.

M919's four saved requests retain their old two-bit low plane in C_CHIP20. Append their high bits in C_CHIP23, preserving the packed prefix and ECP field. The former clock bit at C_CHIP21 keeps its packed position as opaque compatibility data. Encodings remain0 Auto and1..5 for explicit0..4. Reject6/7. Older zero padding gives zero high bits, so old explicit selections keep their meaning. Standalone legacy saves retain their established zero-extension behavior.

Remove Game Port from the M919 menu and its enable path. The board has no such port. Keep the ECP selector at its existing bit and treat the old game bit as ignored compatibility data without shifting the packed layout. Clear the game decoder during normal peripheral application.

The user explicitly supersedes the inherited detected-order settings contract. Version0.9.7 uses fixed physical Setup positions and the matching runtime policy. No format migration, provisional label or Setup bus probe is added. Historical T3 clauses about ordinal rebinding are superseded only in that scope.

FIFO, bus-master DMA, cache engines, power management, controller discovery frameworks and speculative bus-speed changes are outside scope. Software tests do not establish electrical timing margins.

## Implementation and validation

Keep one coherent implementation boundary for shared mode service and all port consumers. Extend the existing M919 proof and shared ATA fixtures rather than adding a parallel firmware stack. Add per-port limits and an optional controller timing adapter, complete common two-device discovery/reset integration, extend M919 policy/UI/persistence and remove Game Port. The generic driver supports0..4; a controller adapter can lower that ceiling. Do not cap a port merely because the IDE controller is separate from the chipset. MP386 has onboard IDE. Increment versions for changed firmware behavior.

Current source versions are M9190.9.7, PB4300.2.2, Presario0.2.2 and MP3860.3.2. Later patches add the independent shared AT DMA cascade setup and the M919 reset and Setup corrections. The patch versions include the shared previous-command ERR repair. M919 also removes the unsupported revision/clock veto, establishes the FDC initialization bit from cold state, and removes the blanket upper-RAM cache veto. MP386's previously published0.2.0 identity is not reused. PB430 places the shared reset include and new PIO module after its fixed F065 compatibility entry. Other ports keep their established placement. The ROM integrity check retains fixed entries, reset targets, VGA regions and split-lane reconstruction.

Build private images first. Run the named changed-path checks once, bounded existing disk completion/width checks, current settings consumers affected by the packed extension, and ROM integrity for each physical image. Reuse unchanged cache and peripheral qualification. Complete documentation, fresh boundary trace and one native full review before the local commit and standard candidate promotion. The user subsequently confirms PIO4, stable revision3.4 settings and working VLB, and approves0.9.2 review/publication. Further PCI tuning remains deferred. The revision3.4 unit's Super I/O is reported as UM8670F. Relaxed timing temporarily restored its floppy, but the fault recurred. Microsoft EMM386 Ctrl+Alt+Del also remains unresolved there. The user accepts both limits for publication. OEM-reproduced VLB palette corruption with sampled sound remains a separate accepted limit. No all-clock electrical qualification is claimed. The ignored task result records the complete validation reconciliation and unchanged-owner reuse for final review.
